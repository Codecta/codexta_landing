MERCHANT GUIDE

Codexta for WooCommerce

How to install and connect the Codexta Assistant plugin, set up the assistant your shoppers talk to, and work with the back-office assistant and reports in your WordPress admin. Each task names the exact place, the buttons to press, who can do it and whether it depends on your plan.

Places are written as WooCommerce › Codexta Assistant › Settings › Team: the WooCommerce menu in the WordPress admin, then the Codexta page and its own menu. Things you can type in the chat look like “Set up my assistant”. Unfamiliar words such as guideline, lesson or guest are explained in the glossary.

01

Getting started

Four steps take you from the plugin to a working assistant: install the plugin, connect your shop, get activated by Codexta, and run the guided setup.

How do I install the plugin?

  • Who: a WordPress administrator
  • Plan: any

WordPress admin › Plugins › Add New Plugin › Upload Plugin

  1. Get the Codexta Assistant plugin from us (see Codexta for WooCommerce).
  2. Upload the .zip file and press Install Now, then Activate Plugin.
  3. The plugin needs WordPress 6.4, PHP 7.4 and WooCommerce 8.0 or newer. It works with High-Performance Order Storage and the Cart and Checkout blocks.

The plugin does nothing until you connect it. Nothing is sent to Codexta before that, and the assistant is not shown on your storefront.

How do I connect my shop?

  • Who: a WordPress administrator or shop manager
  • Plan: any

WordPress admin › WooCommerce › Codexta Assistant

  1. Press Connect to Codexta.
  2. WooCommerce shows its own screen asking you to approve access for Codexta Assistant. Approve it.
  3. You come back to the plugin page. It shows Connected to Codexta. and Status: Connected, with the Codexta page below it.

There are no keys or passwords to copy: WooCommerce creates the access key, and the plugin and Codexta set up the rest themselves. If you see The connection attempt expired. Please click Connect again., press Connect to Codexta again. While connecting, Codexta starts your knowledge base from your shop’s name and description, its published pages and its product categories.

The Settings part of the plugin page holds the Codexta URL and an optional Server URL. Leave them as they are unless we ask you to change them.

Why does the assistant not answer yet?

  • Who: Owner
  • Plan: agreed with Codexta

WooCommerce › Codexta Assistant › Settings › Plan

WooCommerce has no app billing, so a newly connected shop waits for Codexta to activate it on the plan you agree with us. Until then every Codexta page shows:

YOU SEEWaiting for activation by Codexta. Your assistant will not answer shoppers until Codexta activates it; contact Codexta to agree the plan.

Shoppers who open the chat meanwhile read:

SHOPPERS SEEThe assistant is not available right now. Please try again later.

Contact us to agree the plan. You can already open the Codexta page and look around, but the assistant does not answer shoppers, and changes to the knowledge base, authoring and enrichment wait for activation too.

How do I run the guided setup?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Overview › Set up your assistant

  1. Press Set up my assistant. Codexta opens Assistant › Chat and sends “Set up my assistant” for you.
  2. The assistant lists five areas: Assistant identity, Knowledge base, Voice and handover, On the storefront and Test. Each shows as done, partly done or missing. Then it asks How do you want to go on? Choose Go through what is missing, Review everything, Just one area or Stop here.
  3. Answer its questions. It asks which languages your shoppers write in and drafts a name, a greeting and up to four starter questions. Then it fills the knowledge base from your shop’s own pages, such as shipping, returns, payments, the FAQ and contact. It may ask for your shop’s web address.
  4. Before anything is saved, it shows you the exact text. A plain “yes” to a list of drafts approves exactly that list.
  5. In the Test step it asks a few real questions and shows which note answered each. Questions about orders, stock, prices or the cart cannot be tested from the admin: try those on your storefront.

You can skip any area, stop and come back later. Anything already done is kept. To continue or start again, type in Assistant › Chat:

  • “What is left to set up”
  • “Run the setup again”
  • “Add my shipping and returns pages to the knowledge base”

The card stays on the Overview until you press Dismiss. Dismissing is remembered for this shop in this browser. The assistant never asks for passwords or API keys.

03

Knowledge base

The knowledge base is a set of notes the assistant answers from: shipping, returns, sizing, care, contact details and anything else shoppers ask. When you connect, Codexta starts it with notes about your shop, one for each published page, and your product categories, under the shop/ folder. Everyone with access can read notes; only the Owner, Admins and KB editors can change them.

How do I add a note?

  • Who: Owner, Admin, KB editor
  • Plan: any

WooCommerce › Codexta Assistant › Knowledge base

  1. Press New note.
  2. Enter a path relative to the knowledge base, for example faq/shipping.md, and press Create.
  3. Write the note. Switch between edit, split and preview to check it.
  4. Press Save.

How do I import or export notes?

  • Who: Owner, Admin, KB editor (import); anyone who can open the page (export)
  • Plan: any

WooCommerce › Codexta Assistant › Knowledge base

  1. Press Import and choose a .zip export or one or more .md files.
  2. Optionally enter a Target folder (empty = the root), for example imported/faq.
  3. Press Preview. Files are grouped as Changed, Unchanged, Not imported and Rejected. Tick Overwrite {n} changed files if you want to replace existing notes.
  4. Press Import {n} notes.

To export, press Select, tick notes and press Export selected, or press Export all.

How do I add a web page or a PDF?

  • Who: Owner, Admin, KB editor
  • Plan: any

WooCommerce › Codexta Assistant › Knowledge base › Add document (web page or PDF)

  1. Enter the page address, for example https://example.com/shipping.
  2. To include linked pages on the same site, tick Also the pages it links to on the same site and set how many (up to 50).
  3. Press Add page (or Add site). For a PDF, use the file picker instead.

The document becomes a note in the sources/ folder that the assistant can answer from.

How do I keep a web page note up to date?

  • Who: Owner, Admin, KB editor
  • Plan: any

WooCommerce › Codexta Assistant › Knowledge base › (a note added from a web page)

  1. Press Sync from source to fetch the page again. You see Synced: the page changed or Synced: no change.
  2. To sync automatically, set Sync by itself to daily or weekly.

How do I delete a note?

  • Who: Owner, Admin, KB editor
  • Plan: any

WooCommerce › Codexta Assistant › Knowledge base › (the note)

  1. Open the note and press Delete.
  2. Confirm Delete {path}? This cannot be undone.

Notes can only be deleted here. The chat does not delete notes; it merges or rewrites them instead.

How do I enrich a note?

  • Who: Owner, Admin, KB editor
  • Plan: not on every plan (ask us)

WooCommerce › Codexta Assistant › Knowledge base › (the note)

  1. Open the note and press ✦ Enrich.
  2. Codexta extracts the people, places, projects and organisations in the note into its tags.

If your plan does not include enrichment, it is refused.

How do I add to the knowledge base by chatting?

  • Who: Owner, Admin, KB editor
  • Plan: any

WooCommerce › Codexta Assistant › Assistant › Chat

  1. Ask with a clear writing word — document, record, add, write up or publish. For example:
    • “document how to …”
    • “Add my shipping and returns pages to the knowledge base”
    • “sync my FAQ”
  2. When a procedure changes, ask it to update the note; it rewrites the section rather than adding a second version.

Reading your shop’s pages into notes is part of the guided setup, which only the Owner and Admins can run.

What if the knowledge base is full?

  • Who: Owner, Admin, KB editor
  • Plan: limits differ by plan

Each plan allows a number of notes; your limit and how many you have are in Settings › Plan. When you reach the limit, creating, importing or adding a document stops with:

YOU SEEThe knowledge base holds {n} of the {quota} documents the {plan} plan allows. Delete a document or upgrade the plan.

Your current count is on Settings › Plan under Knowledge base notes. To raise the limit, contact us.

04

Fix a wrong or missing answer

Every time a shopper asks something the knowledge base has nothing for, Codexta records it. The shopper is not told.

How do I answer questions the assistant missed?

  • Who: everyone sees the list; Owner, Admin and KB editor write the notes
  • Plan: any

WooCommerce › Codexta Assistant › Conversations › Unanswered

  1. Each row shows a question and how often it was asked, for example “asked 3 times in 2 conversations”. The Overview tile Questions the KB missed opens this list too.
  2. Press Write KB article.
  3. The knowledge base asks Write a knowledge base article? with the question as the title. Press Create note.
  4. Write the answer and press Save.

When the list is empty it reads Nothing unanswered. Every question found something in the knowledge base.

How do I find out why an answer was wrong?

  • Who: Owner, Admin, Support manager, Support agent, Viewer (to read)
  • Plan: any

WooCommerce › Codexta Assistant › Conversations › All › (a conversation)

  1. Find the conversation with Search (words, session or shopper id) or the Outcome, Shopper, Channel, From and To filters, then press Apply.
  2. Open it. What the assistant did lists events such as Knowledge base had no answer or Handed to a person, and the Transcript shows which tool the assistant used.
  3. Correct the note in the Knowledge base, or ask the assistant in Assistant › Chat to document the right answer.

In Settings › General, tick Name the knowledge-base article an answer came from so answers name their note.

05

Teach the assistant: lessons and preferences

There are two kinds of “remember this”. A lesson is a rule for how the assistant treats your shoppers. A preference is how the assistant works for the person who asks, whether that is you, a colleague or a shopper. Facts your shop publishes, such as delivery times, returns or opening hours, are neither: put those in the knowledge base. If it is unclear which you mean, the assistant asks once.

How do I teach the assistant a rule for my shoppers?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Assistant › Chat

  1. Say what the assistant should do, and that it is for your shoppers. For example:
    • “Remember this for my shoppers: when someone asks for a gift idea, ask for their budget first.”
    • “From now on, when a shopper asks about sizes, suggest our size guide before recommending a size.”
  2. The assistant asks which of your shoppers’ conversations the lesson is for, offering up to four, for example WooCommerce shop - Product search and recommendations or WooCommerce shop assistant. Pick one or more. If you already named one, it skips this question.
  3. It shows the rule as it will store it, for example:
    YOU SEEWhen a shopper asks for a gift idea, ask for their budget before suggesting products.
    Press Save it, or Change it and say what to change. Nothing is stored before you approve the text.
  4. It confirms which conversations the lesson was stored for. Shoppers get it from their next conversation.

Lessons are stored in your own knowledge base and reach only your shop’s shoppers. The assistant refuses a lesson that contains a person’s name, email or order, or that promises a discount, refund or delivery date your policies do not state, and says why. If a lesson on the same topic already exists, it tells you and shows its id instead of adding a second one.

How do I see or remove lessons?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Assistant › Chat

  1. Ask “What lessons do I have?” or “Show what you were taught for product search”. You get a table of each lesson’s id, title and rule, for example lessons/woocommerce_search/ask-budget-first.
  2. Say which one to drop, for example “Forget the gift budget lesson”. If more than one could match, it asks which.
  3. It asks you to confirm the ids. Press Remove it, or Keep it to cancel.
  4. It says what was removed. Shoppers stop getting it from their next conversation.

Remove lessons through the chat as above rather than editing the notes in the Knowledge base page.

How do I set how the assistant works for me?

  • Who: anyone who can open Assistant › Chat
  • Plan: any

WooCommerce › Codexta Assistant › Assistant › Chat

  1. Say how you want it to work for you. For example:
    • “Always answer me in short bullet points.”
    • “When I ask for orders, show date, customer and total as a table.”
  2. It may ask whether this applies everywhere or only in one area, such as the back-office assistant. It then confirms what it saved and where.
  3. To check or undo: “What are my preferences?” shows them, and “Forget my table preference” removes one.

Your preferences are yours: colleagues and shoppers do not get them. A preference cannot switch off a confirmation or a safety step, for example “never ask me before changing a product”. The assistant says it cannot save that.

Can shoppers set their own preferences?

  • Who: any shopper in the storefront chat
  • Plan: any

Yes, there is nothing for you to switch on. A shopper can tell the storefront assistant how they like to be helped, for example:

  • “Keep your answers short, please.”
  • “I wear EU size 39, remember that.”
  • “Always show me the cheapest option first.”

The assistant keeps it for that shopper only and applies it to their later chats too: for a signed-in customer on their account, for a guest in the same browser. Asking “What do you remember about me?” shows it, and “Forget my size” removes it. A shopper’s preference never changes what the assistant tells other shoppers and never overrides your lessons or policies.

06

Name, greeting, starter questions and languages

How do I change them by chatting?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Assistant › Chat

  1. Type “Change the greeting and starter questions”, or run the guided setup.
  2. The assistant drafts the shop’s display name, its own name, a short greeting and up to four starter questions. It offers a translation for each language your shoppers use.
  3. It shows the exact text and saves only after you approve.

The chat cannot change the accent colour, widget position, widget theme, What your store sells, Allow guests or chat limits. Change those in Settings › General.

How do I change them in Settings?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Settings › General

  1. Store: Store name and What your store sells (one or two sentences the assistant keeps in mind in every chat).
  2. Assistant: Assistant name, Accent colour, Widget position, How the assistant writes, Reply window, Knowledge base language and Widget theme.
  3. Greeting and suggested questions: Greeting and Idea 1 to Idea 4. Leave the ideas empty to use the assistant’s defaults.
  4. Who can chat: Allow guests, Conversations per shopper per day and Guests’ share of monthly conversations (%).
  5. Press Save settings. You see Saved.

What do the other assistant settings do?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Settings › General › Assistant

  • Your website and Draft from my website (under Store): Codexta reads your site and fills the store name, description, greeting and ideas. You see Drafted from your website: review it below, then save. Nothing is saved until you press Save settings.
  • How the assistant writes: Precise (0.2), Balanced (0.5) or Creative (0.9). Default keeps Codexta’s own setting. Precise sticks closest to your notes; Creative words answers more freely.
  • Reply window: Answer each message at once, or Wait {n} seconds for more lines (3, 5, 10 or 15). This is useful when shoppers type a question in several short lines: they get one answer to all of them. While it waits, the chat shows Sending in a moment; add more if you like.
  • Knowledge base language: the language your notes are written in. A question in another language is also searched in this one, so a shopper writing in German still finds an English note.
  • Name the knowledge-base article an answer came from: when ticked, answers from your notes name the note they came from.
  • Widget theme: System (follows the shopper’s device), Light or Dark. Accent colour is the main colour of the chat button and window; Widget position puts the button Bottom right or Bottom left.

Press Save settings. The chat window picks up the change the next time a shopper opens it.

How do I add a language?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Settings › General

  1. In Store or Greeting and suggested questions, choose a language from + Add language.
  2. Fill in its tab. Left empty, the default wording is used.
  3. Press Save settings.

The chat window shows the wording for the language your store is shown in, and the default in every other language. The assistant replies in the language the shopper writes in. The chat window’s own buttons and labels come in English, Croatian, Bosnian, German, French and Spanish.

07

The storefront assistant

Once your shop is connected, the plugin adds the chat button to your storefront by itself. There is nothing to place in your theme, and no on/off switch inside Codexta.

How do I turn it on or off?

  • Who: a WordPress administrator
  • Plan: any

WordPress admin › Plugins

  1. To take the assistant off for a while, Deactivate the Codexta Assistant plugin. The chat button disappears and Codexta starts no new conversations for your shop.
  2. To bring it back, Activate the plugin again. Your setup, notes and conversations are kept.
  3. Open your shop and check whether the chat button is shown.

A developer can keep the chat button off on some pages or until a visitor accepts your cookie banner, with the plugin’s codexta_widget_enabled filter. Until Codexta activates your shop the assistant does not answer: shoppers read The assistant is not available right now. Please try again later. Who may chat and how much is in Guest shoppers and chat limits.

How does the assistant use the cart?

  • Who: any shopper
  • Plan: any

The assistant uses the shopper’s own WooCommerce cart, for guests too. What it adds appears in the cart on your pages, which refreshes when it does. It can add, change and remove items, apply a coupon and send the shopper to your checkout. Shipping is settled at checkout, so the assistant quotes the goods without shipping.

What do shoppers see in the chat window?

  • Who: any shopper
  • Plan: any; read aloud and hiding Codexta’s mark are not on every plan (ask us)
  • Under the message box, every chat shows AI assistant. It can make mistakes, so check important information. with a Privacy link to Codexta’s privacy policy. It is shown in the shopper’s language and cannot be switched off.
  • The greeting, the ideas to tap and the assistant’s name come from Settings › General (see above).
  • Read aloud under an answer reads it out (Stop reading stops it). It appears only when your plan includes read aloud.
  • The chat window shows Codexta’s mark. When your plan includes white label, the mark is left out, and if you set no assistant name the window is titled with your store’s name.

Settings › Plan lists read_aloud and white_label among your plan’s features, marked (not included) when they are not part of it.

08

Guest shoppers and chat limits

A guest is a shopper who chats without being signed in to your shop. Anyone can start a guest chat, so you decide whether guests may chat and how much of your monthly conversations they may use. Codexta adds a few limits of its own against abuse. Signed-in shoppers are never held back by the guest limits.

What can a guest do, and what needs signing in?

  • Who: any shopper
  • Plan: any

A guest can ask anything your knowledge base answers, search and compare products, fill the cart and go to checkout, and tell the assistant how they like to be helped. Signed-in customers can also ask about their own orders and request a return. Orders placed as a guest are not linked to a chat, so only signed-in customers’ orders count as assisted orders.

A guest is remembered in the same browser: an open chat is picked up again for 30 minutes after the last message, and their preferences stay with that browser. A new browser, a private window or cleared site data is a new guest. When a guest signs in, the shopper is then recognised by their account on your shop (My account).

How do I let only signed-in shoppers chat?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Settings › General › Who can chat

  1. Untick Allow guests.
  2. Press Save settings.

Guests still see the chat button, but the chat asks them to sign in first:

SHOPPERS SEEPlease sign in to the shop to chat with the assistant.

Allow guests does not apply to Instagram and the other messaging channels: they answer once you connect an account under Settings › Integrations.

How do I limit how many chats one shopper starts?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Settings › General › Who can chat

  1. Enter a number in Conversations per shopper per day. Empty or 0 means no limit.
  2. Press Save settings.

The limit counts new chats per shopper, signed in or guest, per day; the day starts at midnight UTC (London winter time). A shopper who reaches it reads:

SHOPPERS SEEYou’ve reached today’s limit of conversations. Please come back tomorrow.

A shopper you block gets the same message, so they are never told they are blocked.

How much of my monthly conversations can guests use?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Settings › General › Who can chat

Your plan has a number of conversations per month (Settings › Plan, the Conversations meter). Guests may use only a share of them, so a burst of anonymous visitors cannot use up the month and leave nothing for your signed-in customers.

  1. Leave Guests’ share of monthly conversations (%) empty to use your plan’s own share; the field shows it as its placeholder, for example “(plan default)”.
  2. Or enter your own percentage, from 1 to 100. Under the field you see what that means for your plan: Now {share}%: up to {n} of {monthly} conversations.
  3. Press Save settings.

The field is greyed out while Allow guests is off. Signed-in shoppers can always use the rest of the month. When guests have used their share, new guest chats are refused until the next month; guests who are already chatting can finish.

What other limits apply, and who sets them?

  • Who: set by Codexta; ask us to change them
  • Plan: any

On top of your own settings, Codexta applies brakes you cannot change in the app. They protect your monthly conversations from scripts and floods:

  • New guest chats from one internet connection (IP address) are limited per hour.
  • New guest chats for your whole shop are limited per day. The daily number is never more than a thirtieth of your plan’s monthly conversations, so guests cannot spend the month in a few days.
  • Messages from one shopper or one address are limited per minute, for guests and signed-in shoppers alike.

When a guest limit is reached, a new guest chat reads:

SHOPPERS SEEThe assistant is not available right now. Please try again later.

When someone sends too many messages at once:

SHOPPERS SEEToo many messages at once. Please wait a moment and try again.

If real shoppers meet these limits — for example during a sale or a campaign — contact us and we raise them for your shop. The same message is shown when your monthly conversations are used up: the Conversations meter on Settings › Plan tells you whether that is the reason.

09

Conversations, shoppers, events and assisted orders

These pages are open to the Owner, Admins, Support managers, Support agents and Viewers on every plan.

How do I choose what the Overview shows?

  • Who: Owner, Admin (pin); everyone else reads
  • Plan: any

WooCommerce › Codexta Assistant › Events

  1. Choose 7 days, 30 days or 90 days.
  2. In Assistant activity, find a tool with Search tools….
  3. Press the pin to Show on the Overview, or again to Remove from the Overview. Pins are shared with the whole team.

A new shop’s Overview shows Conversations, Resolved or assisted, Assisted revenue, Assisted orders, Handoffs to a person and Questions the KB missed.

How do I read conversations?

  • Who: Owner, Admin, Support manager, Support agent, Viewer
  • Plan: any

WooCommerce › Codexta Assistant › Conversations › All

  1. Filter by Outcome (resolved, assisted, handoff, abandoned), Shopper (guest, customer, social) or dates, and press Apply.
  2. Open a conversation to see its Summary, Shopper, Order from this conversation, What the assistant did and Transcript.

Conversations are read only. Replies from your team show as Shop staff. Conversations are kept for your plan’s retention period.

How do I find or block a shopper?

  • Who: everyone listed above (find); Owner, Admin (block, see email)
  • Plan: any

WooCommerce › Codexta Assistant › Shoppers

  1. Use Search shoppers. Press Conversations on a row to see all their chats.
  2. Press Block or Unblock. Tick Blocked only to list blocked shoppers.

A blocked shopper is told they have reached today’s limit, never that they are blocked. Blocking a guest blocks that browser; a new browser or cleared cookies is a new guest.

What counts as an assisted order?

  • Who: everyone listed above
  • Plan: any

An order counts as assisted when a signed-in customer places it within 7 days after their chat added to the cart or sent a checkout link. It is counted at its total when it is placed. A guest checkout is not linked to a chat, so guest orders are not counted, even when the assistant helped.

10

Support console and taking over a chat

The support console is your helpdesk: press Support console in the Codexta page’s menu bar. Live chats the assistant hands over, tickets, return requests and emails arrive there as cases. The Support console guide explains every part of it, with examples.

How do I switch live chat, tickets or email intake on?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Support console › Settings › Backends

  1. Switch Tickets and incident reports, Live chat with a person or Email intake on or off. It takes a few seconds.
  2. Set live chat hours under Settings › Live chat.

The Overview’s Support card shows what is on and how many cases are open, with Pause for 1 hour, Pause until tomorrow and Resume now. More: switch the helpdesk on.

How do I take over a chat from the assistant?

  • Who: Owner, Admin, Support manager, Support agent
  • Plan: any (live chat switched on)

WooCommerce › Codexta Assistant › Support console › Inbox

  1. A shopper asks for a person, for example “I want to talk to a real person”. Their chat shows Looking for an available agent…
  2. Open the chat under Unassigned and press Assign to me.
  3. Write in Reply. The shopper sees Connected to a human agent and keeps typing in the same window.
  4. When done, press Resolve.

A colleague with the Support agent or Support manager role can take cases after opening the console once; to change their queue or tier, see add a colleague. The full example, and what happens outside live chat hours: live chat.

How do returns and tickets reach me?

  • Who: Owner, Admin, Support manager, Support agent
  • Plan: any

A signed-in customer can request a return of an item from one of their own orders in the storefront chat, with photos of the item and receipt. The return window counts from the date you marked the order completed. Submitting a request does not approve it: it becomes a ticket, and you decide on the order in WooCommerce › Orders. Problems reported in the chat, returns from guests or Instagram messages, and email to your support address become tickets too. In Assistant › Chat you can ask “Any open return requests” or “Any open tickets?”; to answer, assign or close a ticket, use the Support console.

See tickets and return requests and working on a case.

Back-office assistant

In Assistant › Chat, the Store assistant works with your WooCommerce data. KB editors can open the chat but cannot reach store data. Support managers, Support agents and Viewers do not see the Assistant page.

What can I ask?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Assistant › Chat

  • “List this month’s orders”
  • “Show me order #1004”
  • “Which orders are still processing”
  • “Which coupons have expired”
  • “Any open return requests”

It reads orders, registered customers, products including drafts and private ones (a product with sizes or colours as one row per variation), coupons including expired ones, and support tickets. For anything else it can read from WooCommerce — product categories, order notes, refunds, reviews, reports — just ask. A guest checkout has no customer account, and the assistant says so.

How do I make a change?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Assistant › Chat

  1. Ask for the change, for example “Change the price of the Logo Hoodie to 49” or “Create a discount code SPRING10 for 10% off, valid until the end of May”.
  2. The assistant looks up the current value and asks a yes/no question naming the record, the old value and the new value.
  3. Answer yes to apply it. On no, nothing changes. Each change needs its own yes.

It can:

  • change a product’s or variation’s regular and sale price, or end a sale;
  • create a simple product (saved as a draft unless you ask to publish it);
  • change a simple product’s name, description, stock or visibility;
  • create a discount code with the terms you give;
  • keep a note on a customer.

The customer note is kept by Codexta and is not shown in the WordPress admin, because WooCommerce has no customer tags.

Not available in the chat: refunds, cancelling or editing orders, deleting anything, products with sizes or colours (variations), photos and attributes, and staff accounts. Do those in WooCommerce › Orders, Products or Marketing › Coupons.

How do I contact Codexta from the chat?

  • Who: anyone who can open Assistant › Chat
  • Plan: any

Ask the Store assistant to contact support. It asks for an email address for the reply and sends your message. Stop ends a reply in progress and New chat starts over.

Team and roles

There is no invite button. Only WordPress users who can manage WooCommerce can open the Codexta page: administrators and shop managers. A WordPress administrator is always an Owner in Codexta. A shop manager becomes an Admin the first time they open the page; after that the Owner decides their role.

How do I give a colleague a role?

  • Who: Owner (Admins can view the page)
  • Plan: any

WooCommerce › Codexta Assistant › Settings › Team

  1. Give your colleague the Shop manager role in WordPress, and ask them to open WooCommerce › Codexta Assistant once.
  2. Under Members, choose their role in the dropdown. You see Role saved.
  3. To take access away, press Remove. A WordPress user who no longer has the Shop manager or Administrator role cannot open the page.

Only the Owner changes roles. Nobody can change their own role, and the last Owner cannot be removed or demoted. The Codexta staff access panel lists every time someone from Codexta worked in your shop’s data, with the reason they gave.

Authoring

Authoring changes how your store’s assistant behaves — rules, wording and policies such as “never promise delivery dates” — by describing it in a chat. Changes apply to your store only.

How do I change how the assistant behaves?

  • Who: Owner, Admin
  • Plan: not on every plan (ask us)

WooCommerce › Codexta Assistant › Assistant › Chat › Authoring

Start a new chat and choose Authoring at the top. (The other choices are Store assistant, your back-office helper, and Shopping assistant, a preview of what shoppers get.) Then describe the change, for example “When a shopper asks about delivery, never promise a date”. The assistant prepares the change as a draft that you can try first. Shoppers get it only when you say “Publish it”, and only in your store. Authoring changes the assistant’s rules only: not permissions, plans, sign-in, channels or other stores.

See the Authoring guide for worked examples: changing a rule, adding a guideline of your own, trying a change, publishing it and undoing it.

How do I switch an assistant skill off, or take Codexta’s updates?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Assistant › Guidelines

  1. Switch a guideline off for your store, or press Reset to go back to the default. It takes a few seconds.
  2. Under Assistant › Changes › Updates from Codexta, choose View changes, Take the update, Use Codexta’s version (remove my copy) or Keep mine.

More in the Authoring guide: switching guidelines and Codexta’s updates.

How do I check usage or change plan?

  • Who: Owner, Admin (view)
  • Plan: any

WooCommerce › Codexta Assistant › Settings › Plan

  1. See your plan and its status, for example pending or active.

Your team, in the Codexta pages, is told the reason instead: This assistant has reached its conversation limit for this month. Please try again next month, or use another way to get in touch.

What do the features on Settings › Plan mean?

  • Who: Owner, Admin
  • Plan: any

WooCommerce › Codexta Assistant › Settings › Plan

Deactivate, disconnect and your data

  • Deactivating the plugin pauses your shop in Codexta: the chat button disappears and no new conversations start. Activating it again resumes. Nothing is deleted.
  • Disconnecting (the Disconnect button on WooCommerce › Codexta Assistant) or deleting the plugin revokes the WooCommerce access key Codexta used, and Codexta stops working for your shop.
  • 48 hours after you disconnect or delete the plugin, all of your shop’s data in Codexta is deleted. To use Codexta again, install the plugin and connect again.
  • While connected, conversations older than your plan’s retention are deleted every night; the retention period depends on the plan. Daily statistics keep counts only.
  • Deleting a customer in WordPress deletes that customer’s conversations in Codexta automatically.
  • Payments never pass through Codexta: checkout always happens in WooCommerce.

Mention the chat assistant and Codexta in your shop’s privacy policy. See the privacy policy for what Codexta holds and who processes it.
